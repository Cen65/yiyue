# v0.5.0 免费兼容与模拟支付

2026-11-17。模拟流程本地验收完成，未提交/推送。0.4.0已中文提交2808aff。没有配置真实商户，本轮使用明确标注的MOCK渠道，不产生真实扣款或退款。

## 流程

管理员发布排班指定模拟挂号费（分，0免费，最高1000000分）；不可通过客户端覆盖订单金额。收费排班不能直接调用免费预约接口。患者选择时段/就诊人后创建订单，15分钟内模拟支付，成功才生成正式预约。免费排班沿用原流程。

PENDING订单占用一个号源；付款成功转为预约且不重复占用。超时、关闭或停诊释放；之后收到模拟支付结果只进入退款，不重新预约。取消已支付预约和停诊逐单取消在同一事务登记退款；后台完成模拟退款，失败保持REFUND_PENDING并重试。付款与超时共用机构行锁。

管理员对账查看最近200单，对比订单、模拟流水金额和退款标记，显示差异。患者订单最近100条，详情包含医生、院区、时段、就诊人。真实商户验签、外部资金与账单没有实现，不能将已登录患者主动触发的模拟接口当作公网支付回调。

## 配置与API

V6迁移增加价格、payment_order和mock_payment_receipt，无CHECK约束。默认PaymentRunner每5秒处理100条到期/退款任务，`YIYUE_PAYMENT_WORKER_ENABLED=false`可关闭后台；关闭后到期保留需重新启用后台释放，模拟支付接口仍按截止时间判断。

POST/GET `/api/patient/payment-orders`；POST `/{id}/mock-pay`（consent=true）、`/{id}/cancel`；GET `/api/admin/payment-reconciliation`。所有患者操作限制机构与账号并使用会话CSRF。请求幂等键复用，流水按订单唯一。

## 限制

- 收费候补暂不支持；收费建议改约需重新选时段创建订单，原单取消退款。免费候补和改约保持兼容。
- 退款是本地MOCK流水更新，不是外部渠道退款。真实商户签名、回调公网、防重放、账单下载、手续费/部分退款等需要另行设计与验证。
- 系统内最近100单/对账200单，按条详情组装，机构级锁串行；不视作医院生产级吞吐。0.4.0压测报告只适用于当时版本和数据，不直接作为支付版本性能证据。
- 0.4.0 Java强杀恢复演练不等同0.5.0支付事务强杀验证。本轮支付使用真实库并发/故障回归，未做该版本操作系统强杀、外部渠道、Docker实机或远程CI。
- 压测数据触发的变更通知全量IN缺陷已修复，保留十万历史预约进行浏览器回归。
