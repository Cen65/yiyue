# v0.6.0 诊室设备与联合排班

2026-11-19。本地验收完成，未提交/推送。此前v0.5.0已提交bd36efe并推送GitHub main。

管理员进入“诊室与设备”创建ROOM诊室或EQUIPMENT设备，指定院区和状态；同机构同院区同类型名称唯一。发布排班时多选最多20个资源，必须同院区且启用。资源按整场排班独占，患者在排班号源容量内共享；这不是逐人设备检查预约。

医生、诊室、设备同时校验与提交，任一冲突回滚所有写入。占用区间采用[start,end)，相邻可用。停诊释放资源，替诊继承资源和价格，在同一事务转移占用；替诊无效时原占用及排班状态恢复。有正在进行/未来有效占用的资源不能编辑或停用。

## API与迁移

GET `/api/resources`读取当前机构资源，POST `/api/admin/resources`、PUT `/api/admin/resources/{id}`维护；GET `/api/schedules/{id}/resources`读取排班资源。发布排班新增可选resourceIds，旧请求兼容。Controller只做边界处理，Service/Impl负责租户/院区/冲突及事务，Mapper使用MP Lambda，无注解SQL。

V7增加clinic_resource、schedule_resource与索引，无CHECK约束。前后端、启动和Docker路径0.6.0，无新依赖。患者写预约、候补、支付逻辑保持原有容量语义，不重复占用整场资源。
