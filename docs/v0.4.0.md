# v0.4.0 候补与可靠系统内通知

2026-11-17。本地验收完成，已提交2808aff，未推送。v0.3.0已提交9943916，未推送。

患者在已满号源下选择本人/授权就诊人加入候补，“候补与消息”展示医生、院区、时段、就诊人及状态。按加入顺序分配，最长保留10分钟，患者确认后转正式预约。退出或超时释放给下一位；排班停诊终止候补，系统轮询回收保留容量。

通知通过事务outbox投递到系统内消息中心，支持已读。事件与候补状态同事务；消费与投递标志同事务，重复消费不会重复建消息；故障时事件保持未投递，后续轮询重试。无外部渠道凭证和新生产依赖。

## 配置与迁移

V5增加waitlist_entry、notification_event、inbox_message，保留旧预约与排班数据，无新增CHECK约束。不要修改已应用的迁移。默认每5秒轮询，Spring属性`yiyue.waitlist.worker-enabled=false`（环境变量`YIYUE_WAITLIST_WORKER_ENABLED=false`）可关闭候补和消息后台；关闭后需要重新启用才会自动过期/投递，确认接口仍拒绝过期保留。

API统一在`/api/patient`下：POST/GET `/waitlist`，POST `/waitlist/{id}/accept`（consent=true）与`/cancel`，GET `/inbox`，POST `/inbox/{id}/read`。写操作继续使用会话CSRF；所有权、机构与就诊人授权由后端校验。保留与正式预约共享容量，管理员看到的占用也包含候补保留。

## 限制

当前只提供系统内候补通知；短信/邮件送达、人工死信控制台、医院规模压测、Docker实机和操作系统强杀故障注入未验证。数据库持久化及后续轮询恢复测试不等同于全部基础设施故障演练。列表最近100条，单号源长队列与详情组装仍需性能优化。AI实网及医学评估仍待外部条件。
