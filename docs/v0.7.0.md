# v0.7.0 安全、恢复与性能验证

2026-11-19。本轮完成可本地验证的工程项，真实HIS/FHIR、公网证书、商户与医院生产规模验收仍待条件，不称为医院生产就绪。

## 登录与凭证配置

LoginRateLimiter复用既有Redis原子INCR/EXPIRE模式，按真实连接IP及IP+机构+账号固定分钟窗口限流，Redis异常不绕过。键只保存身份摘要，不记录密码或原始IP/账号。普通配置每分钟同身份60次、同IP300次；production配置8/60，超限429。固定窗口不是精确滑动窗口，不支持全网跨IP账号锁定。框架测试中显式关闭限流避免依赖Redis，单元测试及真实HTTPS演练单独验证。

不采信客户端X-Forwarded-For；部署代理时需另行配置可信代理边界，不能开放信任任意转发头。没有修改既有CSRF、Cookie会话、租户/数据权限或容量事务。

production profile启用Spring TLS连接器，PKCS12及密码从TLS_KEY_STORE/TLS_KEY_STORE_PASSWORD注入；安全Cookie强制Secure，保留HttpOnly/SameSite。停止演示数据初始化，但不会删除/禁用旧库既有演示账号。真实环境应使用独立库及独立凭证，不能直接把演示库当作生产库。

production禁用模拟支付API、支付后台及新的收费排班；前端通过已认证`/api/auth/capabilities`读取能力，隐藏支付/价格操作并禁用既有收费号源的预约。免费预约和资源功能保留。真实收款未实现，不能依靠改配置把模拟流水变成真实资金。

真实TLS验证用临时18443端口、自签证书（SAN含localhost/127.0.0.1），客户端仅信任本次证书，不改系统证书库、不关闭证书验证。TLS1.3握手、安全Cookie、8次401后429、伪造转发头无效、模拟API404及收费发布409均已通过。完整公网证书、续期、生产域名与同源静态站点部署不在本轮验收范围。启动示例：设置SPRING_PROFILES_ACTIVE=production、DB_URL/DB_USERNAME/DB_PASSWORD、REDIS_HOST/PORT/PASSWORD、TLS_KEY_STORE及TLS_KEY_STORE_PASSWORD，再运行后端；前端生产构建须由可信TLS同源入口服务，不能把Vite开发服务器当生产部署。

## 备份恢复

`python scripts/backup_restore_drill.py`只操作默认本地演示端口。pg_dump自定义格式备份到`.local/backups`，恢复到随机生成且确认不存在的独立库，不覆盖/删除现有数据库。pg_restore遇错退出，验证22张表行数、逐表内容指纹、容量与资源重叠。

最终结果见verification/v0.7.0-backup.json：源数据前后稳定，恢复库全部表内容指纹一致，容量与资源重叠异常0。数据指纹用于恢复一致性检测；备份文件额外记录SHA256。备份及临时证书/日志仅保存在.gitignore覆盖的.local中，不提交患者数据、凭证或私钥。正式运维还需独立访问控制、加密/异地保管、保留策略和周期演练；本轮没有备份外传或云端凭证托管。

## 性能与测试

Windows/Java21/Spring Boot3.5.7/PostgreSQL17.6/本地Redis，Ryzen7 5700G（8核16线程）/27.9GiB内存，客户端与服务端同一工作站，非独占压测机。沿用load_validation.py，新增1万未来31天之后的排班和10万取消历史预约，累计预约超过20万。四类操作等比例循环：排班分页、本人预约分页、目录、热点号源预约+取消；每级约20秒闭环。准备/登录不计入，操作/秒不是请求/秒（写周期含两次HTTP）。

本轮实际执行：后端`mvn spotless:apply clean verify spotless:check`及能力接口补充后的`mvn spotless:apply verify spotless:check`，68项全部通过（含新增登录限流4项）；前端2项、vue-tsc/Vite构建、Prettier、完整15项浏览器通过。浏览器关闭能力测试使用明确测试桩，HTTPS演练验证真实production API与收费拒绝，两者不混为公网验收。真实HTTP/Redis/PostgreSQL冒烟、Python脚本AST和Git差异检查通过。分页测试已统一等待服务器结果和对应列表渲染，保留历史数据跨页查找，不清空数据或扩大业务返回条数掩盖问题。
