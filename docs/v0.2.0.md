# v0.2.0 AI模块化与基础运营

更新日期2026-11-16。代码版本0.2.0，本地验收完成；代码同步不代表已创建发布标签或GitHub Release。DeepSeek实网及医学评估单独待验收。

## 模块

- yiyue-server：Maven父工程。
- yiyue-common：共享会话身份与业务异常。
- yiyue-ai：导诊Controller/Service/Impl/Req/Resp、DeepSeek客户端、限流及AiDepartmentCatalog端口。
- yiyue-application：启动类、医疗业务、数据库、权限配置及Flyway迁移。

依赖方向application → ai → common，application也直接依赖common。AI通过AiDepartmentCatalog获取当前机构启用科室，数据库适配在application中实现。AI不依赖业务Mapper或PostgreSQL，不是独立微服务，HTTP路径保持不变。

## 基础运营

平台管理员管理机构开户、名称与启停；机构管理员维护本机构院区、科室、医生关联及医护账号。支持新增、编辑、查询、启停与重名校验。机构停用后账号登录和已有会话失效。院区/医生有未结束排班时拒绝停用，不能绕过未来停诊改约流程。

同一医生可关联多个院区与科室，按指定科室出诊。医生冲突判断仍跨所有院区。配置变更与排班创建共用机构行锁；医生排班沿用医生行锁。复杂数据在Service组装，单表查询使用MP Lambda。

患者可建立本人或已授权家属档案，提交时明确确认授权。代预约校验tenantId、ownerId及authorized；授权撤销与预约锁定同一档案行。撤销授权后仍允许原账号取消已经创建的预约。防重索引按就诊人/号源生效，同一账号可为不同就诊人预约。

## 岗位

| 角色 | 数据及操作范围 |
|---|---|
| PLATFORM_ADMIN | 机构开户/启停；不授予医疗业务权限 |
| ADMIN | 本机构基础运营、排班、医护开户及预约处理 |
| RECEPTION | 本机构预约查询和签到，不能完成接诊 |
| DOCTOR | 绑定医生的排班及预约，仅完成本人已签到预约 |
| PATIENT | 本账号管理的档案、预约和导诊 |

每次请求复核账号、机构和角色状态。普通管理员不能通过管理接口升级成平台管理员。查询不返回密码哈希。

## 平台账号初始化

默认关闭。首次需要时，在本地.env配置PLATFORM_ADMIN_ENABLED=true及随机的PLATFORM_ADMIN_PASSWORD（至少12个字符且UTF-8不超过72字节），重启服务。机构编码platform、账号platform_admin。仅首次创建，不覆盖已有密码。首次完成后可关闭初始化开关；普通管理员权限不会改变。

平台开户设置机构编码及管理员初始账号/密码。登录页直接输入新机构编码，然后管理员维护院区、科室、医生和医护账户，再发布排班。

## 构建与迁移

IDEA导入yiyue-server/pom.xml，运行yiyue-application中的com.yiyue.YiYueApplication。父工程mvn verify构建全部模块；mvn -pl yiyue-ai -am test单独验证AI与common，无需数据库。

本机Start-Local.ps1指向yiyue-application/target/yiyue-server-0.2.0.jar。Dockerfile与CI已适配多模块，Docker实际运行待验证。

Flyway V1保持原样；V2新增运营状态、医生关联、就诊人及排班科室，并回填旧医生关联和本人档案；V3调整预约防重索引。没有新增CHECK约束，不清空业务表。已应用迁移不可修改，后续变更新增版本。

## 接口

- /api/platform/tenants：GET/POST；PUT /{id}，仅平台管理员。
- /api/admin/operations：GET；POST /{kind}、PUT /{kind}/{id}，kind为campuses/departments/doctors，另可更新tenant名称。
- /api/admin/operations/staff：POST，name/username/password/role/doctorId，role为DOCTOR或RECEPTION。
- /api/patient/profiles：GET/POST；PUT /{id}，POST /{id}/revoke。name/relationship/consent。
- /api/staff/appointments：GET；POST /{id}/{action}，前台check-in、医生本人complete。
- /api/schedules/page：GET，page/size/campusId/departmentId/doctorId/date；MP分页返回records/total/current/size。

预约可增加patientId，不传仍使用本人档案；列表增加patientId/patientName。排班创建可增加departmentId，不传使用主科室。原有查询端点保留以兼容旧调用方。所有写请求仍需CSRF。

## 验证与限制

29项后端测试（AI11、业务18）、2项前端测试、9项浏览器测试、构建、格式和真实PostgreSQL/Redis HTTP冒烟通过。平台界面浏览器测试使用明确测试桩，真实开户/权限/停用会话由数据库与MockMvc集成测试验证。AI仍未实网调用或完成医学有效性评估。

运营基础档案列表和医生预约范围组装尚未针对超大数据量优化；排班主页面已服务端分页，旧/schedules暂保留。未实现岗位变更、密码重置、停诊改约、候补、支付、短信或设备联合预约。未验证Docker实机、医院级性能与高可用。
